# 连接与通知配置

Telegram统一使用：填写 BotFather Token → 保存设置 → 生成绑定码 → 在机器人私聊发送完整 `/bind 绑定码`。绑定码五分钟有效、一次性使用；重新生成、修改配置或停用会使旧码失效。无需 Chat ID、测试消息或公网回调。使用独立机器人；已有 Webhook/其他实例轮询可能占用机器人。绑定成功和启动后自动注册命令菜单；各应用保留自己的业务命令。Token 留空保留已保存密钥，更换 Token 必须重新绑定。

图床仅管理员可配置机器人、绑定并取图；普通用户原有上传和随机图权限不变。随手传机器人沿用管理员配置与原有账户消息归属。今日想看沿用单管理员配置。固件保持既有项目权限模型，通知移除 Telegram，保留 Webhook/MQTT；旧凭据与历史不会被清除。

Webhook可直接测试当前表单，测试不保存、不启用配置。空密钥只在服务端合并已保存值；保存与测试互斥，表单改变后旧测试结果不再显示。Webhook 填写 URL、请求方法、正文类型、请求头和模板；固件因签名发布事件和 MQTT 具有单独渠道表单。

共享模块 `internal/integrationtest`（有 server 目录的项目位于 server 下）提供受限请求、安全错误和绑定码逻辑；前端 `draft-test.js` 防止异步结果覆盖新草稿。图床保留原有电报接入表单样式：设置、绑定、指令说明依次展示，绑定状态自动刷新。修改共享代码后须同步所有镜像并运行模块与适配器测试。

所有配置沿用原有管理员/项目权限，不增加个人配置副本或改变用户管理。备份必须保留整个数据目录和应用密钥。
